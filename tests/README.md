# The fork's own recorded tests

`mise run test:ci` runs upstream [MesenTests](https://github.com/nesdev-org/MesenTests) (cloned
into `bin/Tests`) and then the `.mtp` files in this folder, and fails if either fails. This folder
holds tests for what MesenTests doesn't cover, starting with the system-level gaps left by the
CPU verification work. See `docs/research/mesentests-improvement-plan.md` for the plan and the
criteria a test has to meet.

Everything here must be redistributable. The test ROMs are written for this fork, so their
source is in `src/` next to the recording.

| Test | ROM source | What it checks | Expected values from | Closes |
|---|---|---|---|---|
| `SMS/z80_timing.mtp` | `SMS/src/z80_timing.s` (WLA-DX) | T-states of 14 Z80 instructions, timed with the VDP V counter: the six whose timing the fork fixed, the DDCB BIT alias, and controls | Zilog UM0080 | sms-verification-findings #9 (system-level gap) for instruction timing |
| `SNES/sa1_timing.mtp` | `SNES/src/sa1_timing.s` (ca65) | SA-1 cycles for NOP, ROM/I-RAM/BW-RAM loads, BRK+RTI and COP+RTI, timed with the SNES PPU V counter | WDC W65C816S datasheet, BW-RAM at half speed, MesenCE's PRG-ROM return penalty (see the ROM's header comment) | snes-verification-findings #15 (system-level gap) for the vector-fetch fix (#12) |

Each ROM prints a row per case (expected, measured, OK/NG) and ends on "ALL PASS" or the number of
failures. `<name>.png` is the result screen at the time of recording. **Both ROMs were checked
against cores with the corresponding fix reverted:** the SMS ROM reports the pre-fix timings from
sms #2–#3 (8 failures), and the SA-1 ROM reports BRK/COP 2 cycles short.

## Working with the tests

| Task | What it does |
|---|---|
| `mise run build:test-roms` | Assembles `*/src/*.s` into `bin/test-roms/` (`tests/tools/build-roms.sh`). The font is generated by `tests/tools/font.py` |
| `mise run test:record -- <rom> <out.mtp> [--frames N]` | Records a `.mtp` headlessly from power-on with no input (`tools/mtp-record`), then replays it the way the CI runner does and fails unless every frame matches |
| `mise run test:record-fork` | Rebuilds the ROMs and re-records every test in `manifest.txt` |
| `mise run test:ci` | Runs upstream MesenTests, then this folder |

A recording pins down MesenCE's current output; it doesn't prove that output is correct. Before
committing a new or re-recorded `.mtp`, check its `.png` against the expected result. A re-recording
that changes the result needs a findings-log entry saying why the new result is right.

Re-recording produces the same frame hashes, but the number of repeats of the final screen can
differ by a frame (the recorder stops on a timer), so the `.mtp` bytes may change without any
behaviour change.

## Running on hardware

The ROMs are meant to be run on real consoles too, which turns the expected values into
hardware-verified ones (plan §4.3). Build them with `mise run build:test-roms`, then:

- `bin/test-roms/z80_timing.sms`: any SMS flashcart. Game Gear: the same ROM should run, but the
  screen layout assumes the SMS resolution.
- `bin/test-roms/sa1_timing.sfc`: a SNES flashcart with SA-1 support.

Record the console model, flashcart and firmware, and a photo of the result screen, in the
relevant findings log.
